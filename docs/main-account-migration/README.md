## 当前流程

表格候选 → 商品ID路由 → 完整扫描对应主品绑定 → 已有效绑定直接闭环；未绑定/已删除则检查佣金 → 主号两项合作达人授权 → 等待达人确认则立即返回 → 生效后再次检查并加入现有计划 → 全量复核 → 事务快照/动作账本 → 表格回写并读回。

## 执行与阶段控制

- `main_authorization_rollout.json` 的 phase：`preview`只列清单；`canary`仅处理 canary_record_ids；`active`交由正常轮询全天处理。
- 正常轮询不改变原有单实例、浏览器互斥与播报优先纪律。每张表默认每轮10条，复查间隔30分钟。
- `main_account_flow.py --preview --output ../docs/main-account-migration/preview.json`：实时读取四主品，绝不写业务表、业务数据库或发消息；只保存指定预览文件。需在投流工作目录使用便携Python，或直接指定脚本绝对路径。
- `main_account_flow.py --apply --record RECORD_ID`：遵循同样阶段闸门、商品、佣金、停投和互斥保护。不会运行分部ROI、预算、启停或日报任务。
- `main_account_flow.py --apply --all`：本轮处理所有符合条件的候选，单条失败不阻断后续记录。
- `poll_and_run.py --dry-run`：只列离线候选，不把未核验当作未绑定。

## 口径与状态

关系的唯一键为主号＋达人＋商品＋计划。跨表同键只执行一次并分别回写；同达人不同主品必须独立检查。
已有自动拉取和手动授权均视为有效；自动拉取回写“主号已拉取”，手动有效关系回写“主号已加入”。

|结果|表格状态|
|---|---|
|主号授权未完成或读取暂时失败|待主号授权|
|已申请，达人尚未确认|等待达人接受|
|已生效，待加入或等待预约日期|待加入主品|
|手动有效绑定/新增后已核实|主号已加入|
|自动拉取且在对应商品计划内|主号已拉取|
|非四主品、人工停投、平台明确拦截|待人工处理|
|佣金超过现有阈值|佣金过高|

历史分部“已投放/已完成”永远不因重试重开。旧分部授权、建计划断点不算主号成功。
明确人工停投优先；同键的另一个表格记录存在停投要求时也不添加。未到预约日期可以先授权，暂不加入。
分页总数未核实、翻页不完整、行无法解析、账号或商品不符时，禁止执行授权或加入。

## 账本与恢复

沿用 `投流/webui/assets/webui.db`，新增 main_product_scans、main_product_bindings、main_product_workflows、main_product_record_sync、main_product_events。
保存版本、主号、商品、计划、步骤结果和复核时间，不存合作码或授权凭据。
平台提交结果不明时，下轮先查对应主品绑定，不能依据响应异常重复添加。
平台成功后若表格更新失败，pending sync只补表格同步，不重复授权或添加；表格读回一致才标记同步成功。

主品参数不变校验覆盖编辑器输入及开关；只允许既有计划的“保存”，不使用创建/发布回退。
若平台要求修改ROI才能保存，保留平台阻塞原因，不擅自改主品ROI。

主号监控脚本 main_pull_daily.py 使用相同商品配置，归属和“填表未拉取”均按达人＋目标计划计算。原有09:10/13:30/17:30任务不变。

## 本轮上线核验

已执行真实单条授权验证并读回表格，随后开启 active；四主品由原桌面轮询接续处理。
本机生成的 execution-summary.md 区分既有绑定、真实授权待确认、平台拒绝及技术暂挂，不把待确认写成失败。逐条业务结果不随源码提交，可用 devtools/summarize_execution.py 从本机台账重新生成。
真实新增绑定须以授权生效后的完整绑定复核为准；已有手动关系的“主号已加入”不表示本次新添加。

浏览器互斥：主号授权、主号监控扫描及手动入口共用 browser_poll.lock/单实例；长批次只续期自己的标记。
主号流程只打开一个自有临时页，不关闭或借用其他业务标签；原分部页面保护规则保持不变。
记录之间若遇启停/日报忙标或距下一播报不足8分钟，即结束本轮释放锁。等待达人点击确认只保存断点，下轮继续。

便携 Python 验证：main_account_flow 60项模拟测试、auth_policy 3项策略测试通过（不代表所有真实达人均已确认）。
原轮询仍由桌面 poll_runner 管理；桌面关闭后不能仅靠 automation.enabled 推断后台持续运行。

开发辅助脚本位于 devtools：retry_blocked.py 只针对指定记录补查；summarize_execution.py 只读台账生成结果。
一次性实施和诊断留档仅保留在本机，不作为日常命令或源码发布。
